# 首次真实 Windows 鼠标单击验收手册

> **当前状态：未验证。** 这份手册和 `web/input_acceptance.html` 是在准备
> 阶段写好的，编写过程中没有执行任何真实鼠标/键盘操作，也没有开启真实
> 输入。所有依赖真实桌面、真实浏览器和真实 `SendInput` 的性质，都必须
> 在下面的验收流程真正执行后，才能把「未验证」改成「已验证」。

本次验收只回答一个问题：

> 佳能否在用户逐次授权后，对指定的验收页面按钮产生**恰好一次**左键
> 单击，并且之后的屏幕观察能看到计数变化？

不包含：键盘输入、双击、拖拽、滚轮、连续点击、批量点击、工作流连续
执行、多显示器边界、负坐标、UAC 提权窗口、锁屏界面。它们需要单独的
验收，不要混进第一次真实点击。

## 一、准备

### 1. 使用可丢弃的环境

**建议优先使用可丢弃的 Windows 虚拟机。** 虚拟机应满足：

- 没有个人文件、聊天记录、密码库或生产环境凭据；
- 可以随时回滚快照或直接删除；
- 不是通过远程桌面（RDP）会话操作；真实输入会发到交互式桌面，
  远程会话、锁屏或切换用户会改变前台和桌面状态；
- 屏幕缩放和分辨率固定，验收中途不要改 DPI 或显示器布局；
- 只保留一个显示器参与本次验收。

如果只能在日常使用的电脑上做，先接受这个风险：真实点击一旦落到错误
位置，可能操作到别的窗口。以下保护仍然必须做。

### 2. 保存并清理现场

- **确保没有重要文件处于待保存状态。** 先保存所有文档，关闭不需要的
  程序；
- 桌面上不要放可执行文件、删除按钮、回收站或重要文件图标；
- 验收窗口放在屏幕中央，完整可见，不被其他窗口遮挡；
- 关闭可能弹出通知的聊天软件、更新提示和录屏/远程控制工具；
- 记下当前前台窗口和鼠标位置，验收结束后便于判断是否发生意外操作。

### 3. 打开验收页面并确认初始状态

服务按平常方式启动后，用本机浏览器打开：

```
http://127.0.0.1:8000/input_acceptance.html
```

如果配置了别的回环地址或端口，以 `run.py` 打印的地址为准。

确认：

- 窗口标题是「佳 Agent 首次真实点击验收页（勿关闭）」；
- 页面只有橙色的「测试按钮：请单击我一次」；
- **当前点击次数显示 `0`**；
- 页面没有加载任何外部图片、字体或脚本，也不需要联网。

如果计数不是 `0`，刷新页面或重新打开，恢复到 `0` 后再开始。不要把
「已经有计数」的页面当作首次点击验收。

确认测试页面已打开，并且你能清楚看到它。验收过程中不要手动点击这个
按钮——那会污染计数，让「0 → 1」失去意义。

### 4. 确认真实输入仍然关闭

真实输入需要**两个既有条件**同时满足，缺一不可：

| 条件 | 位置 | 本次验收前的状态 |
| --- | --- | --- |
| 配置开关 | `config/tools.yaml` 的 `input.real_mouse_enabled` | 必须是 `false` |
| 进程环境变量 | 启动服务的终端里的 `JIA_ENABLE_REAL_MOUSE` | 不设置，或不是 `1` |

在准备阶段运行只读检查工具：

```
.venv\Scripts\python.exe scripts\check_first_click_readiness.py
```

它会检查页面没有网络调用、手册要点齐全、两个条件都没有满足、登记处
没有构造真实后端。**它不会开启真实输入，也不会点击。**

此时真实输入开关仍处于关闭状态。**恢复急停不能代替启用真实输入的两个
条件**：急停只是阻止输入；恢复急停不会打开配置、不会设置环境变量，也
不会构造真实后端。

如果急停当前处于生效状态，先在本机页面上按正常流程显式恢复；恢复之后
真实输入仍然需要两个条件同时满足。

### 5. 理解后续授权边界

在真正验收时，启用真实输入需要由**你本人主动**完成两个条件：

1. 把 `config/tools.yaml` 改成 `input.real_mouse_enabled: true`；
2. 在启动服务的同一个终端里设置 `JIA_ENABLE_REAL_MOUSE=1`。

只满足一个条件时，真实后端不会被构造，`click_element` 会在弹授权卡片
之前失败关闭。修改配置后需要重启服务才能生效；**本次准备阶段不修改、
不重启**，这些动作只在你决定正式验收时手动执行。

即使两个条件都满足，**每次点击仍需用户单独确认**。启用输入不等于授权
某一次点击；佳每次都必须先观察、固定目标、弹出授权卡片，等你确认后
才能发送一次左键单击。模型、网页按钮和恢复急停都不能绕过这张卡片。

服务端还有硬性速率限制：两次真实点击至少间隔 **1 秒**，每分钟最多
**5 次**，每次工具调用最多一次左键单击。本次验收不要触发这些上限，
更不要为了「测试限制」而连续点击。

## 二、操作过程

以下步骤在正式验收时执行。**每次验收只执行一次左键单击，不进行连续
点击。** 不要用键盘回车或空格去触发按钮；本次只验证鼠标左键单击。

1. **让佳观察，不要让它点击。** 对佳说：
   「请观察当前屏幕，找到标题包含『首次真实点击验收页』的窗口和其中的
   测试按钮。只观察，不要点击。」
   屏幕观察本身可能需要一次确认；那只是截图授权，不是点击授权，不要
   和后面的鼠标点击确认混在一起。
2. 佳调用 `inspect_screen` 后，核对这些信息：
   - 窗口标题能对应到验收页面；
   - 识别出的元素里有「测试按钮：请单击我一次」；
   - 当前计数是 `0`；
   - 观察是单窗口范围，不是整桌面。
3. **让佳准备点击。** 说：
   「请点击验收页面里的测试按钮一次，只点一次。」
   佳只能提交 `observation_id` 和 `element_id`，不能提交坐标。
4. **核对授权卡片，先不要确认。** 卡片应显示：
   - 目标应用（通常是浏览器进程）；
   - 目标窗口标题包含「首次真实点击验收页」；
   - 目标元素是「测试按钮：请单击我一次」；
   - 「本次会产生真实鼠标输入」以及真实后端名称；
   - 坐标由服务端计算，模型没有指定坐标；
   - 执行前还会核对窗口身份、位置、前台和桌面安全。
5. 任何一项与预期不符，点「拒绝」。拒绝后计数必须仍然是 `0`。
6. 只有全部符合预期，才点一次「允许」。**确认一次后就不要再点按钮，
   也不要反复按回车或鼠标。**
7. 等待结果。只允许出现一次点击：
   - 计数从 `0` 变为 `1`；
   - 不允许从 `0` 直接跳到 `2` 或更多；
   - 不应该出现双击、拖动或鼠标卡住的感觉。
8. **重新观察屏幕。** 点击后旧观察记录已经失效，必须让佳重新调用
   `inspect_screen`（不是复用刚才的记录），确认它读到「当前点击次数：1」。
9. 记录结果和时间，然后按第六节关闭真实输入。

### 建议先做的失败路径演练

这些演练都**不应该产生任何输入事件**，可以在真正的那一次成功点击之前
完成。每做完一个演练，重新观察、重新确认状态，再做下一个。

- **拒绝授权：** 让佳准备点击，在卡片上点「拒绝」。计数必须保持 `0`。
- **观察记录过期：** 让佳观察后等待超过 **30 秒**（观察记录有效期
  30 秒），再让它点击。应在弹卡片前失败，计数保持 `0`。
- **窗口变化：** 让佳观察后，在确认前移动或改变验收窗口大小；确认后
  应被拒绝，计数保持 `0`。
- **急停：** 在授权卡片出现后、确认前按急停。等待中的确认应被取消，
  计数保持 `0`。演练后按正常流程恢复急停；恢复不会启用真实输入。

失败路径演练也必须在真实输入已经启用、但尚未确认点击的状态下进行，
才能证明「拒绝时没有输入事件」。如果只是在真实输入关闭时点拒绝，那只
验证了工具不可用，不是本次验收要证明的性质。

## 三、验收标准

只有下面 8 项全部有明确证据，首次真实点击验收才算通过。**未实际执行
或没有记录的项，一律标记为「未验证」。**

| # | 标准 | 怎么判定 | 状态 |
| --- | --- | --- | --- |
| 1 | 佳能识别测试页面和测试按钮 | 观察记录里的窗口标题、元素名称正确 | 未验证 |
| 2 | 授权卡片正确显示目标窗口与按钮 | 卡片上的应用、窗口标题、元素名称与服务端固定的目标一致 | 未验证 |
| 3 | 确认后只产生一次预期的左键单击 | 计数只增加 1；没有双击、拖动或额外点击 | 未验证 |
| 4 | 页面计数从 0 变为 1 | 点击前 `0`，点击后 `1` | 未验证 |
| 5 | 后续屏幕观察能识别计数变化 | 新的 `inspect_screen` 明确读到计数 `1` | 未验证 |
| 6 | 拒绝授权时没有输入事件 | 拒绝后计数仍为 `0`，桌面无变化 | 未验证 |
| 7 | 观察记录过期、窗口变化或急停时操作被拒绝 | 三种演练都在点击前停止，计数不变 | 未验证 |
| 8 | 输入结果未知时不自动重试 | 代码和离线测试覆盖；真实验收中若出现 `unknown`，停止且不重试 | 未验证 |

第 8 项**不应为了验收而主动制造**。离线测试已经覆盖「`unknown` 不自动
重试」；真实验收只需要在意外出现时遵守停止规则。真实桌面上的 `unknown`
处理仍属于**未验证**。

## 四、停止条件

出现以下任一情况，**输入结果未知时立即停止，不允许重试**：

- 鼠标点到了验收按钮以外的任何位置；
- 计数不是从 `0` 变为 `1`，或者一次出现多个计数；
- 授权卡片的目标窗口、按钮、后端类型有任何不一致；
- 佳报告 `failed` 或 `unknown`；
- 窗口在确认前后移动、改变大小、被遮挡、失去前台，或屏幕/DPI 变化；
- 出现 UAC、锁屏、切换用户、远程桌面断开等安全界面；
- 鼠标左键疑似卡在按下状态，或出现拖拽痕迹；
- 你无法确定刚才发生了什么，或对现场没有把握。

停止动作：

1. 立刻按本机页面上的「急停」；
2. **不允许重试**，不要让佳「再点一次确认」；
3. 不要再让佳点击，先人工检查桌面、前台窗口和鼠标按键状态；
4. 如果左键可能卡住，先人工检查并释放，再继续任何操作；
5. 记录发生时间、当时的前台窗口、计数和佳报告的原始结果。

## 五、验收结束

1. 关闭验收页面和授权卡片；
2. 验收结束后**关闭真实输入**：把 `input.real_mouse_enabled` 改回
   `false`，并移除或取消 `JIA_ENABLE_REAL_MOUSE=1`；
3. 重启服务让配置生效；
4. 再运行一次：

   ```
   .venv\Scripts\python.exe scripts\check_first_click_readiness.py
   ```

   确认两个条件都没有满足、登记处没有真实后端；
5. 确认急停状态符合预期：如果没有发生事故，急停应未生效；如果按过
   急停，决定是否通过本机页面显式恢复。恢复不会开启真实输入；
6. 记录验收结果；如果使用虚拟机，回滚快照或直接丢弃；
7. 不要把为验收而改的配置或环境变量提交到 Git。

## 六、明确标记为未验证的性质

在真正完成一次受控的真实点击之前，以下全部是**未验证**：

- 验收页面在真实鼠标点击下的计数行为（准备阶段没有点过它）；
- 真实浏览器窗口能否被 `inspect_screen` 正确识别，元素框是否准确；
- 真实 `WindowsInputBackend` 在本机的聚焦、前台核对、DPI、坐标命中
  检查和点击结果；
- 授权卡片上的真实进程名、窗口标题、后端名称是否与预期完全一致；
- 安全桌面检测、UAC、锁屏、远程桌面等边界在真实环境下的表现；
- 真实点击后新观察能否稳定读到计数 `1`；
- 真实环境中的 `failed` / `unknown` 分类和鼠标按键释放行为；
- 本地会话、恢复挑战和浏览器前端流程在真实服务上的完整交互（目前只
  有离线 ASGI 测试）；
- 多显示器、负坐标、显示器热插拔和 DPI 变化。

另外，从「最后一次安全检查」到「真正调用 `SendInput`」之间始终存在
竞态窗口。现有检查只能缩小窗口，不能证明它不存在。第一次验收必须按
单次、可丢弃环境、随时可急停的方式执行。
